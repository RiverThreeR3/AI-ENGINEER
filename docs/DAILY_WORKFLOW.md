# Daily AI Engineer Learning, Delivery and Interview Workflow

This document describes how to apply [AI Engineering From Scratch](https://github.com/rohitg00/ai-engineering-from-scratch) to Raphael's learning and professional portfolio. It does **not** prove any local skills have been installed or any scheduled run has produced code.

## One combined daily routine

The existing external ChatGPT automation is scheduled for **08:00 America/Sao_Paulo**; this repository only documents its intended behavior. Keep **one daily report**, not separate notifications for lessons, coding and interviews.

| Mode | Learning | Engineering | Evidence |
| --- | --- | --- | --- |
| BUILD | One verified upstream lesson explained in Brazilian Portuguese, with a complete worked code example, inputs/outputs, alternatives and trade-offs; **no learner exercises or unanswered questions** | One bounded original implementation stage for the **same active flagship** project | Exact branch/PR/SHA, commands and outcomes actually observed |
| AUDIT | Explain an earlier concept or current engineering failure in full; distinguish material presented from skill demonstrated; **no assumed quiz scores** | Inspect the active PR at its actual SHA; test behavior, security, dependency licenses and regressions; fix only with reviewable changes | Tests, CI and deployment distinctly labeled; blockers and next gate |
| SUNDAY | Same lesson and interview obligations | Project status and acceptance-gate audit | **One** private, accurate English master resume generated from verified evidence, preserving prior version when supported |

The scheduled routine alternates BUILD and AUDIT by local calendar days from 2026-11-05 (BUILD) and 2026-11-06 (AUDIT). Sundays do not cancel either part of the learning routine. The combined commercial workflow researches **LinkedIn-only** remote freelance/contract opportunities eligible to Brazil; older cross-platform examples in AGESOMA's watchlist are historical.

## ChatGPT as an expository learning report

**Chosen delivery mode:** the scheduled report is a complete, self-contained **Brazilian Portuguese** explanation of one verified upstream topic with an original worked example, real code path when accessible, input/output walkthrough, technical trade-offs, limitations, and the next concept. Interview preparation includes an authentic **English** question from the upstream bank, an **original English model answer**, and a Portuguese explanation of what a strong response addresses. Once a week, include three such question-and-answer demonstrations and a fully explained system-design example. **Do not ask Raphael to reply, complete exercises, submit quizzes, or attend an interactive mock interview.** This is an adaptation for reading, **not** a claim that upstream interactive skills were executed, a graded evaluation was passed, or the learner has demonstrated proficiency.

**Private persistence:** The user's restricted-access Google Drive learning tracker can be read and updated only via successful, explicitly verified connected Drive actions. It may summarize actual lesson responses, phase checks and interview gaps with timestamps; the tracker is not publicly linked here. If a genuine learner response or assessment is absent, record `Not evaluated` without requesting an answer and never infer completion from receiving the report. The full curriculum's `LEARNING.md` and course project's `PROJECTS-LEARNING.md` are optional private local state files, not public portfolio files.

**Public career proof:** The sanitized [recruiter-facing evidence map](RECRUITER_GUIDE.md) links each project to real GitHub code, acceptance criteria, reproducible checks and honest limitations. The private professional resume and its weekly refinements reference the **same stable project/CI links**. Interview coaching targets these same technical decisions, but personal answers/scores do not become recruiter-visible content.

**Weekly reconciliation:** Match the official `applied-ai-engineer.json` readiness criteria to: upstream lesson **presented for reading** → any separately observed learner practice (optional; otherwise not evaluated) → attributable original project PR/commit SHA → reproducible test/evaluation → evidence-backed CV bullet → explained interview topic. Flag missing steps and do not promote learning-only accomplishments to CV experience.

- [`build-project`](https://github.com/rohitg00/ai-engineering-from-scratch/blob/main/skills/build-project/SKILL.md): **one project stage per learning session**, with learner-written attempts, staged grader and feedback. This does **not** establish a new-projects-per-week quota.
- [`interview-prep`](https://github.com/rohitg00/ai-engineering-from-scratch/blob/main/skills/interview-prep/SKILL.md): authentic prompts from the bank, answers withheld until Raphael responds, measured feedback and linked learning gaps.

The upstream skills above describe their **native interactive behavior**, not the mode used by this scheduled report. Reading an explanation is **not equivalent** to completing an interactive upstream stage, learner-authored practice, or a graded interview. Commercial BUILD tasks may use coding agents subject to independent verification; agent-generated code does not itself demonstrate the learner's technical mastery.

## Daily report — required fields, in Brazilian Portuguese

1. **Source check:** exact upstream phase/lesson/route, URL, checked revision if actually available, relevant changes or `unverified`.
2. **Career alignment:** LLM Product Engineering route stage and why it relates to a current verified client need.
3. **Lesson:** full readable explanation, verified code or explicitly labeled pseudocode, original worked example with inputs/outputs, alternatives, trade-offs and limitations; no exercises or unanswered questions.
4. **Interview:** authentic bank-linked prompt in English, original English model answer and Portuguese coaching commentary; no response or grading required.
5. **Project stage:** current flagship, original files/PR/SHA, independent tests, CI for the **same** commit, failures and next acceptance gate.
6. **Portfolio evidence delta:** new reproducible measurements and limitations; `none verified` if there was no new proof.
7. **Audit and next action:** planned vs delivered, security/quality gap, blockers, and an achievable next step.

Do not describe planned activity as delivered, a locally completed tutorial as professional experience, or a passing test as production deployment. Verify a source before asserting a new upstream version or license.
